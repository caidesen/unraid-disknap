# DiskNap 详情页分析设计

> 这是早期设计记录，含未采用或已调整的方案。当前功能以 README 为准：详情页展示休眠率趋势、唤醒次数趋势、休眠时长分布和硬盘对比；不展示旧累计值或数据覆盖率。

本轮交付为设计方案及使用演示数据的可交互原型，不修改生产插件或服务器。目标是让用户判断休眠效果、识别反复启停和定位值得排查的时间段。

## 页面要回答的问题

1. 硬盘实际休眠得怎么样？看选定窗口内的有效休眠占比。
2. 哪块盘反复唤醒？看观察到的转换次数和完整休眠时长，而非仅比较累计运行时间。
3. 什么时间发生？看状态时间轴，再钻取到区间和记录。
4. 这些结论可信吗？始终显示有效数据覆盖，未知和采集中断必须留白。

## 信息架构

- Main 保持轻量概览和详情入口。
- 详情默认最近 24 小时，提供 7 天及自定义范围；范围变化时统一刷新全部指标。SQLite 历史不足时显示真实可用区间，不补齐成全天。
- 全部硬盘或单盘选择。保留已离线设备的历史身份，设备名及盘位变化不合并不同 ID。
- 顶部三个指标：休眠占比、观察到的唤醒、完整休眠中位时长。覆盖率在时间窗口旁持续显示。
- 分析提示只列有证据的事实，例如“disk1 有 8 段完整休眠不足 30 分钟”，点击定位对应时间段，不做健康评分。
- 状态时间轴以盘为行，共用真实时间轴；运行、休眠、未知三种状态。点击片段显示起止时间、估算时长和相邻转换。
- 硬盘对比表按指标排序：休眠占比、观察到的唤醒、完整休眠中位时长、最长观测连续运行、覆盖率。每盘可展开区间分析。
- 原始记录折叠到底部，用于核查，不占据首页主要位置。

## 指标定义

| 指标 | 计算与解释 |
|---|---|
| 有效休眠占比 | 休眠秒数 ÷（休眠秒数 + 运行秒数）；未观测时长不进入分母。全部硬盘按有效磁盘秒加权 |
| 数据覆盖率 | 有效运行和休眠时长 ÷ 应观测时长。单盘从该设备首次纳入监控与所选窗口交集开始计算，离线、未知、间断单独列出；全部硬盘以各盘应观测时长之和为分母 |
| 观察到的唤醒 | 连续有效观测中 sleep → awake 转换数；不是 SMART 启停次数 |
| 完整休眠时长中位数 | 两端都观察到状态转换的休眠段时长中位数。窗口边缘、首次观察、未知相邻段不算完整样本；没有完整段显示样本不足 |
| 最长观测连续运行 | 所选窗口内最长连续运行段，遇重启、缺测或未知即中断；窗口截断段标注“至少”或“窗口内”，不能声称实际开始/结束时间 |
| 短休眠段 | 首版将完整且不足 30 分钟的休眠段作为描述性线索，展示段数和分布；不等同于故障或寿命损耗结论 |

不把高唤醒次数直接判为异常：使用时段、盘的角色和有效覆盖会影响解释。若要比较昨天或前七天，仅在设备集合、时间范围和覆盖可比较时展示差值，否则提示无法比较。

## 数据处理

1. 以 observations.id 及 boot/uptime 保留采集顺序，墙上时间仅用于时间坐标。时钟回拨处断开并标记，避免重叠片段。
2. 使用 disk_samples 的区间增量及 interval_start 恢复有效运行/休眠区间。转换发生的具体时刻只知道位于两次采样之间，保持“按上一状态估算”的口径。
3. 缺失记录、unknown、boot 变化、interval_start 为空都不能连接成连续休眠。不能用两条相距很远的同状态记录把中间补满。
4. 查询范围需要读取边界前后的记录，以识别区间是否完整；对时长按窗口及小时/日期边界裁切，不能把跨午夜的全部时长归到结束日。
5. 迁移前的累计基数只展示在“自开始监控累计”中，不混入最近 24 小时或每日分析。逐次历史不足时不推算过去。
6. 长时间范围按小时或天聚合，在查询端限制结果量；图形聚合不代表数据变成零，未知仍须保留。

现有表足够支持首版，不加新采集器、不需要修改采样周期。要更准确估计历史上“应观测的设备集合”和采集故障原因，后续可增加明确的启用/停用及采集错误事件；当前不能从 unknown 判断是设备拔出、阵列停止还是采集失败。

## 首版范围

优先实现：统一时间和硬盘筛选、三个核心指标、覆盖率、状态时间轴、硬盘对比、完整休眠段分布与可核查事实提示，原始记录折叠。

后续再做：同等窗口环比、小时热力图、任务时间对照。现有数据无法直接证明哪个进程唤醒了硬盘，也不能算出真实节电金额；这些功能分别需要额外活动来源和硬件功耗参数。

## 原型说明

`work/disknap-analysis.html` 全部使用模拟数据，固定 24 小时和 5 分钟采样，展示全部硬盘/单盘选择。模拟 08:00–09:00 缺测、disk1 的多次短休眠，验证缺测不会被算作休眠。范围选择、片段钻取和正式查询尚未实现。

## 验收要点

- 全休眠、全运行、零记录、仅未知、新盘、离线盘不产生误导性的 0% 或 100% 指标。
- 完整睡眠段和窗口截断段分开，未知和重启中断连续段。
- 跨日、范围裁切、时钟回拨、改变采样间隔后不重复累计。
- 单盘与全部加权指标一致；覆盖不足和历史不足有明确说明。
- 生产实现需测试聚合结果，不只测试页面里出现了指标名称。

短休眠分析需考虑采样分辨率：采样间隔达到或超过 30 分钟时，不展示“短于 30 分钟”的段数结论；更粗的采样无法支持该判断。所有唤醒次数均为观察到的次数，不能当作真实启停总次数。

原型已用隔离脚本验证演示占比、缺测覆盖、单盘选择和恢复交互；未验证浏览器布局。原型中的完整休眠样本不足状态也已检查。

## 图表版补充

交互预览：`work/disknap-charts.html`，使用模拟数据，三块盘的图例保持同一顺序；原生图例用于显示/隐藏某块盘，图内提供数值提示。

1. **每日休眠占比折线图**：横轴日期，纵轴 0–100%。回答“最近哪块盘的休眠效果在变化”。只用有效观测时长计算比例，覆盖率不足的天标为缺测或注明低覆盖，不能把少量观测解释成整天表现。
2. **按小时唤醒柱状图**：横轴本地小时，纵轴所选窗口内观察到的唤醒总次数，按盘分组。回答“哪些时段最值得对照任务”。缺测小时显示未知；若改为比较唤醒强度，必须按有效观测小时归一化并明确单位，不能把总次数当频率。
3. **完整休眠时长分布横条图**：不足 30 分钟、30–60 分钟、1–3 小时、3–6 小时、6 小时及以上，组内按盘比较。分桶区间左闭右开，最后一桶无上界；仅统计完整休眠段，不能把片段估算成完整段。采样分辨率不足时隐藏不支持的细分桶或提示无法判断。

三张图分别表达“趋势、时段、连续休眠质量”，随后接单日状态时间轴用于定位。原始记录继续折叠在末尾，指标说明与数据覆盖保留。首版不堆叠饼图、仪表盘或无依据的健康评分。

原型的柱状图总次数与分布完整段数是独立演示指标：窗口截断、未知间断可导致唤醒次数与完整休眠段数不同，不能强求两者相等。
